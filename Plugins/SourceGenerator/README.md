# EncosyTower Roslyn tooling

[`EncosyTower.SourceGen.slnx`](EncosyTower.SourceGen.slnx) is the standalone workspace for
EncosyTower source generators, analyzers, diagnostic suppressors, code fixes, formatting
refactorings, tests, and compiler-host samples. Use this solution for SourceGen work; the repository
root solution is generated by Unity and is not the SourceGen build target.

The current solution contains 38 projects:

- 17 production Roslyn projects;
- one MSTest project;
- 20 compiler-host sample projects.

Production projects target .NET Standard 2.0, compile with C# 10, and use Roslyn 4.3.1. The test
project targets .NET 8 with C# 12, while samples target .NET Standard 2.1 with C# 11. The production
inventory currently contains 32 incremental generators, 30 diagnostic analyzers, eight diagnostic
suppressors, six exported code-fix providers, and 12 formatting refactoring providers.

## Project layout

| Area | Projects and responsibility |
|---|---|
| Shared | `EncosyTower.SourceGen.Common`, `EncosyTower.SourceGen.Helpers`, `EncosyTower.SourceGen.Data.Helpers`, `EncosyTower.SourceGen.Helpers.Variants` |
| Core | `EncosyTower.Core.Generators`, `EncosyTower.Formatters` |
| Data | `EncosyTower.Data.Generators`, `EncosyTower.Data.CodeRefactors` |
| Database Authoring | `EncosyTower.Databases.Authoring.Generators` |
| Entities | `EncosyTower.Entities.Generators`, `EncosyTower.Entities.CodeRefactors` |
| Entities Stats | `EncosyTower.Entities.Stats.Generators` |
| MVVM | `EncosyTower.Mvvm.Generators`, `EncosyTower.Mvvm.CodeRefactors` |
| Persistence | `EncosyTower.Persistence.Generators` |
| Processing | `EncosyTower.Processing.Generators` |
| PubSub | `EncosyTower.PubSub.Generators` |
| Validation | `EncosyTower.SourceGen.Tests`, plus the projects under [`Samples`](Samples/) |

Each feature has one `*.Generators` assembly containing both its incremental generators and
component analyzers. The `CodeRefactors` assemblies contain analyzer and code-fix pairs, while
`EncosyTower.Formatters` contains interactive code-refactoring providers.

The source layout keeps the roles separate without changing namespaces:

```text
EncosyTower.Core.Generators/
  EnumExtensions/
    Analyzers/
    Generators/

EncosyTower.Processing.Generators/
  Analyzers/
  Generators/
```

## Build and test

Requirements:

- a .NET SDK that can build the .NET 8 test project;
- `UNITY_OS_INSTALL_ROOT` set to the Unity installation root;
- this Unity project opened at least once so `Library/ScriptAssemblies` contains the required Unity
  and package assemblies.

From this directory, use Debug for normal validation:

```powershell
dotnet build EncosyTower.SourceGen.slnx --configuration Debug --nologo
dotnet test EncosyTower.SourceGen.slnx --configuration Debug --no-build --nologo
```

Build outputs and test results are written below `Build/<ProjectName>/` by default. Set
`ArtifactsPath` to redirect them to an isolated root.

The test suite checks exact generated source and hint names, output compilation, analyzer
diagnostics, code fixes, suppressors, and incremental caching. Verified snapshots live beside their
feature tests under `EncosyTower.SourceGen.Tests/**/Snapshots`.

## Unity package artifacts

UPM is the supported deployment unit; the repository defines no `.nupkg` publication contract.
Release builds copy each production project's `$(TargetPath)` to its configured Unity package
destination and produce only the retained `*.Generators.dll` files. Debug validation does not update
package files.

| Projects | Artifact destination under `Packages/com.laicasaane.encosy-tower` |
|---|---|
| Core generator assembly; Common, all Helpers, and Formatters | `EncosyTower.Core/SourceGenerators` |
| Data generator assembly and code refactors | `EncosyTower.Data/SourceGenerators` |
| Database Authoring generator assembly | `EncosyTower.Databases.Authoring/SourceGenerators` |
| Entities generator assembly and code refactors | `EncosyTower.Entities/SourceGenerators` |
| Entities Stats generator assembly | `EncosyTower.Entities.Stats/SourceGenerators` |
| MVVM generator assembly and code refactors | `EncosyTower.Mvvm/SourceGenerators` |
| Persistence generator assembly | `EncosyTower.Persistence/SourceGenerators` |
| Processing generator assembly | `EncosyTower.Processing/SourceGenerators` |
| PubSub generator assembly | `EncosyTower.PubSub/SourceGenerators` |

Feature projects override `UnityAnalyzerDestination`; shared and Core projects use the default Core
destination from [`Directory.Build.props`](Directory.Build.props). The test project is excluded
from copying. Run a Release build only when intentionally refreshing tracked package artifacts, and
keep the Unity Editor closed while replacing those DLLs.

Production Roslyn Release builds disable Source Link in
[`Directory.Build.targets`](Directory.Build.targets) so a commit-only revision change does not alter
otherwise identical shipped DLLs. Debug builds, tests, and samples retain the SDK's default Source
Link behavior.

## Inspect generated sources

Generated-source persistence belongs to the compiler host, not to generators. For an MSBuild
consumer, enable the standard compiler properties:

```xml
<EmitCompilerGeneratedFiles>true</EmitCompilerGeneratedFiles>
<CompilerGeneratedFilesOutputPath>
  $(IntermediateOutputPath)Generated
</CompilerGeneratedFilesOutputPath>
```

Captured files are inspection artifacts. Do not add them to `Compile`, place them under `Assets`,
or include them in UPM or Release inputs. EncosyTower generators accept no output-path property or
additional file and perform no direct file I/O.

The current repository does not expose a public Unity menu or a shipped capture bridge for this
workflow. Unity-side response-file capture support remains internal to the development tools and
its tests.

## Roslyn dependencies

Production components pin Roslyn 4.3.1 for Unity host compatibility:

```xml
<PackageReference Include="Microsoft.CodeAnalysis.CSharp"
                  Version="4.3.1"
                  PrivateAssets="all" />
```

Code-fix and formatting projects also reference
`Microsoft.CodeAnalysis.Workspaces.Common` 4.3.1. To verify the compiler bundled with an installed
Unity Editor, inspect `[UnityInstallRootPath]/Editor/Data/DotNetSdkRoslyn/csc.deps.json`.

## Debug a generator

Install the [.NET Compiler Platform SDK][compiler-platform-sdk], then set
[`EncosyTower.Core.Generators`](EncosyTower.Core.Generators/EncosyTower.Core.Generators.csproj) as
the Visual Studio startup project. Its
[`launchSettings.json`](EncosyTower.Core.Generators/Properties/launchSettings.json) uses
`DebugRoslynComponent` and runs against `Samples/Samples.Data/Samples.Data.csproj`.

[compiler-platform-sdk]: https://learn.microsoft.com/en-us/dotnet/csharp/roslyn-sdk/tutorials/how-to-write-csharp-analyzer-code-fix#install-using-the-visual-studio-installer---workloads-view
